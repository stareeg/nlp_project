# Детектор юридических ссылок

FastAPI-сервис для извлечения ссылок на нормы российского права из обычного текста. Сервис принимает текст, находит документ из `law_aliases.json`, разбирает статью, пункт или часть и подпункт, после чего возвращает нормализованный список объектов.

Проект выполнен для группового задания №1. Решение рассчитано на четыре скрытых набора по 500 текстов и ограничение в пять минут. Основной путь не использует нейросети, внешние API и сетевые запросы: результат воспроизводим, а время работы почти линейно зависит от длины текста.

## Что реализовано

- 1 055 документов и 18 724 исходных алиаса загружаются из выданного словаря.
- Полные названия распознаются в разных падежах.
- Поддерживаются сокращения: `НК РФ`, `УК РФ`, `АПК`, `КоАП РФ`, `ФЗ №...` и другие варианты из словаря.
- Распознаются `статья`, `ст.`, `пункт`, `п.`, `часть`, `ч.`, `подпункт`, `пп.` и падежные формы.
- Поддерживается частая опечатка `пунта`.
- Работают прямой и обратный порядок реквизитов.
- Перечисления статей, пунктов и подпунктов раскрываются в отдельные объекты.
- Несколько ссылок в одном предложении не смешиваются между собой.
- Для одинаковых норм удаляются дубли.
- Для неоднозначных алиасов учитываются номер и дата документа.
- Если точный поиск не сработал, запускается ограниченный поиск опечатки в названии документа.
- Название документа без статьи, пункта или подпункта не считается ссылкой на конкретную норму.

Пример:

```text
пп. 1, 2 и 3 п. 2 ст. 3 НК РФ
```

Результат:

```json
{
  "links": [
    {
      "law_id": 15,
      "article": "3",
      "point_article": "2",
      "subpoint_article": "1"
    },
    {
      "law_id": 15,
      "article": "3",
      "point_article": "2",
      "subpoint_article": "2"
    },
    {
      "law_id": 15,
      "article": "3",
      "point_article": "2",
      "subpoint_article": "3"
    }
  ]
}
```

## Почему выбран правиловый алгоритм

В задании фиксирован словарь документов и ограничен формат результата. Для такой задачи правиловый парсер имеет несколько преимуществ:

- не требует обучающей выборки;
- не придумывает отсутствующие ID документов;
- одинаково работает локально и в Docker;
- не зависит от интернета и доступности модели;
- запускается за секунды и обрабатывает тысячи текстов за доли секунды;
- каждую ошибку можно локализовать и исправить отдельным правилом.

Нейросетевая модель увеличила бы размер образа и время запуска, но не решила бы главный вопрос: точное сопоставление названия с `law_id` и корректное раскрытие вложенных перечислений.

## Как работает решение

Обработка состоит из следующих этапов:

```text
Текст
  → нормализация
  → поиск документа
  → извлечение маркированных реквизитов
  → группировка реквизитов
  → разрешение неоднозначного law_id
  → раскрытие перечислений
  → дедупликация
  → JSON
```

### 1. Нормализация

Перед поиском текст приводится к единому виду:

- Unicode нормализуется в NFKC;
- регистр понижается;
- `ё` заменяется на `е`;
- типографские тире заменяются на `-`;
- разные кавычки приводятся к одному виду;
- неразрывные и повторяющиеся пробелы схлопываются;
- `N 127-ФЗ`, `No. 127-ФЗ` и `№ 127-ФЗ` приводятся к форме с `№`.

Пунктуация не удаляется из текста парсера, поскольку точки с запятыми и границы предложений помогают разделять независимые ссылки.

### 2. Работа с падежами

В условии сказано, что алиасы даны без учёта склонений. Поэтому поиск только по строковому равенству пропустил бы нормальную конструкцию:

```text
ст. 30 Гражданского кодекса Российской Федерации
```

Для поисковых токенов применяется компактный русский stemmer. Он приводит `Гражданский кодекс` и `Гражданского кодекса` к одинаковой основе. Stemmer используется только для сопоставления названий и не изменяет значения статьи или пункта.

### 3. Индекс алиасов

Все варианты названий компилируются при запуске в токеновый автомат Ахо-Корасик. Он ищет 18 724 алиаса за один проход по токенам текста.

Токеновый индекс выбран вместо одного огромного регулярного выражения по следующим причинам:

- предсказуемое линейное время поиска;
- отсутствие повторного перебора всех алиасов;
- естественная проверка границ слов;
- возможность выбирать полное название вместо вложенного сокращения.

Если несколько совпадений пересекаются, приоритет имеет вариант с большим числом токенов и большей длиной. Например, `Гражданский процессуальный кодекс Российской Федерации` не распадается на более короткие совпадения.

### 4. Статьи, пункты и подпункты

После определения документа парсер ищет только значения с явными маркерами. Это защищает от дат, номеров законов, сумм и других чисел.

Поддерживаемые формы включают:

```text
ст. 10
статья 10
в статье 10
статьи 10, 11 и 12
п. 2
пункт 2
пункта 2
часть 3
ч. 3
пп. а
подпункт 1
в подпунктах а, б и в
```

Допустимые значения:

```text
12
30.1
3.345
а
12а
43.2-6
1, 2, 3
5 и 6
```

Значение с дефисом, например `43.2-6`, сохраняется одной строкой. Оно не раскрывается как числовой диапазон, потому что в исходном задании такой формат приведён как допустимое самостоятельное значение.

### 5. Группировка реквизитов

Парсер поддерживает обычный обратный порядок:

```text
пп. 1 п. 2 ст. 374 НК РФ
```

и прямой порядок:

```text
НК РФ, статья 374, пункт 2, подпункт 1
```

Повторный маркер статьи создаёт новую группу. Благодаря этому конструкция

```text
п. 1 ст. 10, п. 2 ст. 15 УК РФ
```

даёт пары `(статья 10, пункт 1)` и `(статья 15, пункт 2)`, а не ошибочное декартово произведение четырёх значений.

Если один маркер содержит перечисление, значения раскрываются:

```text
статьи 105, 158 и 159 УК РФ
```

даёт три объекта с одним `law_id`.

### 6. Несколько документов

Найденные документы служат границами контекста. В тексте

```text
ст. 105 УК РФ и ст. 374 НК РФ
```

статья 105 связывается только с УК РФ, а статья 374 — только с НК РФ.

Дополнительно используются границы предложений и максимальный размер окна. Это уменьшает вероятность присоединить к документу реквизит из предыдущей фразы.

### 7. Неоднозначные алиасы

После нормализации в исходном словаре есть сотни названий, связанных с несколькими ID. Например, один номер федерального закона может встречаться у разных документов, а некоторые короткие заголовки повторяются.

Если совпадение неоднозначно, кандидаты ранжируются по дополнительным данным в окружающем тексте:

1. дата документа;
2. номер документа;
3. специфичность найденного алиаса;
4. детерминированный ID как последний способ разрешить ничью.

Когда в тексте нет сведений, позволяющих различить документы, задача объективно неоднозначна. Сервис возвращает один детерминированный вариант, а не все ID, чтобы не разрушать precision.

### 8. Ограниченный fuzzy fallback

Нечёткий поиск не запускается для каждого текста. Он применяется только при выполнении всех условий:

- найден явный маркер статьи, пункта или подпункта;
- после реквизита не найден точный документ;
- в следующем фрагменте есть хотя бы один токен известного алиаса;
- сходство с лучшим вариантом не ниже установленного порога;
- лучший кандидат достаточно отличается от второго.

Это позволяет разобрать, например:

```text
ст. 34 Граждаснкого кодекса Российской Федерации
```

При этом конструкция `ст. 34 Случайного кодекса` игнорируется.

### 9. Дедупликация

Результаты дедуплицируются по ключу:

```python
(law_id, article, point_article, subpoint_article)
```

Порядок соответствует порядку появления ссылок в исходном тексте.

## Структура проекта

```text
nlp_project/
├── main.py
├── law_aliases.json
├── detector/
│   ├── law_index.py
│   ├── models.py
│   ├── normalizer.py
│   ├── parser.py
│   └── requisites.py
├── tests/
│   ├── test_detector.py
│   └── benchmark.py
├── tools/
│   └── generate_cases.py
├── requirements.txt
└── Dockerfile
```

Назначение модулей:

- `main.py` — модели API, lifespan FastAPI и маршруты;
- `normalizer.py` — Unicode-нормализация, токенизация и русский stemmer;
- `law_index.py` — автомат алиасов, выбор пересечений и разрешение неоднозначностей;
- `requisites.py` — распознавание статей, пунктов, частей и подпунктов;
- `parser.py` — связывание документов с реквизитами и формирование результата;
- `models.py` — внутренние dataclass-модели;
- `test_detector.py` — ручные функциональные тесты;
- `benchmark.py` — воспроизводимый прогон 2 000 примеров;
- `generate_cases.py` — генератор JSONL для дополнительных экспериментов.

## Локальный запуск

Требуется Python 3.12 или новее.

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python main.py
```

Сервис будет доступен по адресам:

- API: `http://localhost:8978/detect`;
- Swagger: `http://localhost:8978/docs`;
- проверка состояния: `http://localhost:8978/health`.

Пример запроса:

```bash
curl -X POST "http://localhost:8978/detect" \
  -H "Content-Type: application/json" \
  -d '{"text":"пп. 1, 2 и 3 п. 2 ст. 3 НК РФ"}'
```

## Запуск в Docker

Сборка:

```bash
docker build -t law-links-service .
```

Запуск:

```bash
docker run --rm -p 8978:8978 --name law-links-service law-links-service
```

Проверка:

```bash
curl http://localhost:8978/health
```

В контейнере используется один worker. Индекс занимает память каждого процесса независимо, поэтому дополнительные workers не ускоряют последовательный учебный benchmark, но увеличивают расход памяти и время старта.

## Тесты

Функциональные тесты запускаются стандартной библиотекой Python, без дополнительного тестового фреймворка:

```bash
python -m unittest -v
```

Проверяются:

- вложенная ссылка;
- несколько законов;
- списки статей и подпунктов;
- повторяющиеся группы статьи и пункта;
- прямой порядок после названия закона;
- часть статьи;
- падежи полных названий;
- опечатка в маркере;
- опечатка в названии закона;
- дефисные значения;
- дедупликация;
- неизвестные документы;
- текст без юридических ссылок;
- цепочки ссылок через запятую, где реквизиты относятся к следующему закону;
- союз «а также» внутри перечисления;
- пустой текст.

## Benchmark

```bash
python tests/benchmark.py                                   # детектор в процессе
python tests/benchmark.py --url http://localhost:8978/detect  # запущенный сервис
python tests/benchmark.py --errors 10                       # показать ошибки
```

Benchmark генерирует четыре уровня по 250 размеченных текстов, по аналогии со скрытыми наборами разной сложности:

1. `1_simple` — одна ссылка, сокращённые маркеры и названия;
2. `2_full_forms` — полные слова в нужном падеже («в соответствии с подпунктом 1 пункта 2 статьи 3»), полные названия кодексов и федеральных законов, перечисления;
3. `3_chains` — длинные тексты с несколькими ссылками подряд через запятую, «и», «а также», общий закон для нескольких ссылок, отвлекающие предложения с числами; сюда же входит пример из условия задания с ручной разметкой;
4. `4_hard` — подпункты в кавычках, `подп.`, слитное написание `ст.10`, `СК РФ`, `КоАП` без «РФ», номер закона после даты.

Считаются precision, recall и F1 по множеству ссылок каждого текста.

Результат через HTTP к сервису в Docker:

```text
1_simple       texts=250 P=1.000 R=1.000 F1=1.000 time=0.70s
2_full_forms   texts=250 P=1.000 R=1.000 F1=1.000 time=0.89s
3_chains       texts=250 P=1.000 R=1.000 F1=1.000 time=0.98s
4_hard         texts=250 P=0.848 R=0.772 F1=0.808 time=1.33s
TOTAL          texts=1000 P=0.951 R=0.922 F1=0.936 time=3.90s
```

Это собственный набор, а не скрытые тесты. Время обработки растёт линейно с длиной текста: текст из условия (~4 000 символов) обрабатывается примерно за 40 мс.

## Генерация дополнительных примеров

```bash
python tools/generate_cases.py --count 5000 --seed 2025 --output generated_cases.jsonl
```

Каждая строка выходного файла содержит текст и ожидаемый список ссылок. Фиксированный `seed` обеспечивает воспроизводимость.

## API-контракт

Запрос:

```json
{
  "text": "Согласно п. 5 ст. 105 УК РФ применяется правило"
}
```

Ответ:

```json
{
  "links": [
    {
      "law_id": 13,
      "article": "105",
      "point_article": "5",
      "subpoint_article": null
    }
  ]
}
```

Все реквизиты кроме `law_id` являются строками, поскольку условие допускает буквенные, составные и дефисные значения.

## Известные ограничения

- Сервис извлекает только документы, присутствующие в `law_aliases.json`. Например, отдельного алиаса Конституции в выданном файле нет.
- Принципиально неоднозначный короткий алиас без номера, даты или названия нельзя разрешить достоверно.
- Fuzzy fallback исправляет небольшие опечатки, но намеренно не принимает сильно искажённые названия: для итоговой метрики ложные документы обычно опаснее одного пропуска.
- Диапазон с дефисом сохраняется строкой и не раскрывается автоматически.
- Парсер ориентирован на явные маркеры нормы. Фраза `по НК РФ` без статьи или пункта не возвращается.

Эти ограничения выбраны сознательно, чтобы сохранить высокую точность, воспроизводимость и время обработки значительно ниже установленного лимита.
