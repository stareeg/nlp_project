# ДЗ 1: поиск юридических ссылок

FastAPI-сервис: на вход текст, на выходе список ссылок на законы (`law_id`, статья, пункт или часть, подпункт).

```json
{"links": [{"law_id": 15, "article": "3", "point_article": "2", "subpoint_article": "1"}]}
```

## Запуск

```bash
docker build -t law-links-service .
docker run -d -p 8978:8978 --name law-links-container law-links-service

curl -X POST "http://localhost:8978/detect" \
     -H "Content-Type: application/json" \
     -d '{"text": "Согласно статье 23 Налогового кодекса и ст. 145 Гражданского кодекса"}'
```

Индекс по `law_aliases.json` собирается при сборке образа, поэтому сервис поднимается примерно за секунду. Без докера: `pip install -r requirements.txt`, потом `python main.py`.

## Тесты

```bash
python -m unittest -v
python tests/benchmark.py
python tests/benchmark.py --url http://localhost:8978/detect
```

`benchmark.py` генерирует размеченные тексты (4 уровня по 250 штук, от простых ссылок до опечаток и цепочек из нескольких законов) и добавляет пример из условия. С флагом `--errors 10` печатает тексты, на которых ошиблись.

## Как работает

Без ML, только правила:

1. Нормализуем текст: нижний регистр, кавычки, тире, пробелы, латинские буквы, похожие на русские. «УК-РФ» и «У.К. РФ» приводим к «УК РФ».
2. Названия законов ищем по словарю алгоритмом Ахо-Корасик по токенам после стемминга, так находится и «Гражданского кодекса». Если точного совпадения нет, ищем название с опечаткой. В словарь добавили сокращения, которых там не было: ГрК, КАС, ВК, ВзК, «ТК ЕАЭС».
3. Рядом с названием ищем статьи, части, пункты и подпункты, перечисления разворачиваем в отдельные ссылки. Диапазоны «10 – 12» и «с 10 по 12» пишем как `10-12`, «части первой» как `1`.
4. Часть кладём в `point_article`. Если есть и часть, и пункт, то пункт идёт в `subpoint_article`.
5. «п. 3 указанной статьи», «ст. 11 того же кодекса», «там же» привязываем к последней найденной ссылке.

Код в `detector/`, сервис в `main.py`.
